# AGENTS.md

Explicador is a Claude Code plugin: an MCP server plus a local web viewer that explains software systems with animated, interactive diagrams.

## Product decisions

Change these only after the user approves:
1. Works with any language: no tree-sitter or LSP; the model provides the understanding.
2. A light index (file tree + import grep, and since F28 an outline of the documents: headings with their lines, data columns) in `.explicador/index/` of the analyzed project is read before code.
3. Scenes are cached in `.explicador/scenes/` and invalidated by hashes of the files they reference.
4. The viewer runs in a local browser tab.
5. Animation types: step-by-step flow playback and zoom between levels, and for lessons (F12, F13) the data's journey, step-by-step value traces, charts that grow, matrices with highlights, worked calculations and a threshold the reader moves. In Present mode (F14) each slide is revealed part by part, with the part's narration as a subtitle under it (F20, S toggles it), slides move in the direction of travel, and each chapter opens with a yellow wipe onto a night-blue card. Since F16 the viewer animates with GSAP from one set of motion tokens (`viewer/src/animation/motion.ts`), and a part taken back with ← plays backwards. Themes decorate the page and the slides with line art that draws itself in, in a composition that changes on every slide (F17); plots trace their curves and a point travels to each mark; a derivation's shared symbols glide between lines; a scatter's classes land and its boundary is traced; particles flow along the active edge of flows and journeys. A concept (F15) opens with its term alone, which then flies to the top while its pieces arrive and its formula assembles symbol by symbol. For vectors (F20) the items of a space land, the query arrives and goes to its cluster, each angle opens with its cosine and the nearest are ranked; a cosine is multiplied, summed, measured and divided before it lands on a gauge; and each chapter of a deep dive opens with the journey as a map, its stop lit. A structure (F25) is drawn as itself and changes state by state: its members glide to their new places, a new one grows out of its parent. A causal system (F26) draws its factors on a ring with signed links and its loops; a push plays through it link by link, each factor lighting up as it goes up or down. An annotated text (F27) marks each quoted part as its note rises beside it; an argument brings its claim, each reason and objection, and its verdict in turn. A figure (F31) draws a physical thing part by part: its arrows and angles draw themselves, its shapes grow in; a trace keeps the steps it played in sight as a strip of cards.
6. Clicking an element opens its detail panel (description, key code); its "Go deeper" button asks the agent to go deeper and its question box asks the agent about the element, both delivered by a plugin monitor (`docs/decisions/interactivity.md`); a read-only code window beside it shows the element's code and plays the agent's code tours. It works without launch flags.
7. Findings are appended to `FINDINGS.md` at the analyzed project's root.
8. Agent output is EXL: Markdown plus a closed catalog of JSX-like tags, with no embedded JavaScript. Lessons (F12, F13) added `<chapter>`, `<stats>`, `<journey>`, `<trace>`, `<chart>`, `<matrix>`, `<quiz>`, `<calc>` and `<threshold>` to the catalog. F16 added `<theme>` (a closed list of themes that decorate a scene) `<plot>` (functions from a closed list, or printed points, with marks) `<derive>` (a formula changed line by line) `<scatter>` (points by class with a decision boundary), `<compare>` (two things row by row) and `<timeline>` (events in order). F15 added `<concept>` (a term with its definition, analogy, formula and example); Markdown may hold LaTeX formulas (`$…$`, `$$…$$`), drawn by KaTeX and checked by the parser. F20 added `<space>` (items, a query and an index's clusters in a vector space) and `<cosine>` (a cosine worked out step by step), `kind="vector"` on trace values and `stage` on `<chapter>`. F23 added `<brief>` (the audience, the question, one example, the misconception, the check and the terms, decided before any slide): every scene opens with one, `render_scene` refuses a scene without it, and it is never shown. F24 added `arc` on every component (its part of the narrative: question, example, idea, contrast, apply, answer, check, recap), with warnings for the order (the example before any idea or answer), terms and acronyms defined before use, and label titles. F25 added `<structure>` (a tree, an organization chart or a file tree, with `<member>`s and the `<change>`s that move it from state to state). F26 added `<system>` (factors, signed links, the loops the parser finds, and one `<push>` followed by `<effect>`s). F27 added `<annotated>` (a passage and the notes on its quoted words) and `<argument>` (a claim, reasons, objections with replies, a verdict), and a warning when no component draws the brief's form. F28 added refs to a document's section, `path#Heading`, which the server resolves to lines. F31 added `<figure>` (circles, boxes, arrows, angles, zones and labels on a grid, revealed by `<show>`) and the everyday box kinds `person`, `object`, `place`, `signal` and `step`; the viewer's own words follow the scene's language (Spanish or English).

## How to work

- The approved plan and phase status live in `.dev/PLAN.md`. Work one phase at a time:
  1. Write the phase into `.dev/TASK.md` (goal, files, plan, validation) before touching code.
  2. Make the smallest change that meets the phase criterion, reusing what exists.
  3. Run the checks below and record the real results in `TASK.md`.
  4. Reset `TASK.md` to `# Current Task` + `No active task.`, mark the phase in `PLAN.md`, and commit.
  5. Stop at the end of each phase with a summary of what was done, what is pending and how to test it; wait for the user's go-ahead.
- When something is ambiguous, ask the user with multiple-choice options instead of assuming.
- Write code, docs and commits in English; talk to the user in Spanish. At runtime the skill makes Claude answer in the user's language.
- Re-check the official docs (code.claude.com/docs) before changing the plugin manifest, skills, monitors or MCP config; last verified 2026-11-09.
- `spikes/` holds disposable prototypes; their conclusions live in `docs/decisions/`.

## Checks and commits

- A change is done when `npm run typecheck` and `npm run lint` exit 0 and `npm test` passes (server, viewer and the comprehension bench in `evals/test/`; run `npm run build` first: some tests need the built viewer). Changes to the viewer also need `npm run e2e` (Chromium; CI runs Firefox and WebKit).
- `npm run eval` and `npm run eval:comprension` call other models and cost usage: never run them, nor any other test with a model other than the session's, without telling the user first (with the cost at list price) and getting their go-ahead. The comprehension eval runs Haiku only; Sonnet and Opus need the user's say-so for each run.
- The phases F22–F30 (from valid format to a scene that is understood) are in `docs/plan.md`: its scope and criteria per phase come first, and the stops are at the end of F22, F25 and F30.
- Commit as `abdair-coca <cocaabdair@gmail.com>` with Conventional Commits, one commit per finished phase, without `Co-Authored-By` or other attribution lines.
